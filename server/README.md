# Сервер транспорта Qvarch

Связывает копии приложения между собой. Сейчас на нём:
- устройства — вход по ключу, без учётных записей;
- чаты, ветки разговоров, реакции, упоминания, вложения (результаты блоков);
- общие заметки, папки и доски (Yjs), их картинки и файлы, результаты запусков, комментарии.

Дальше сюда же встанут модулями совместная работа, присутствие «в сети», аналитика и задачи другим людям.

- **Стек.** Node 22, одно WebSocket-соединение на приложение (`/v1`), PostgreSQL.
- **Образ.** Один, `qvarch/transport`. База — официальный `postgres` рядом в `compose`, данные в томе.
- **Проверка жизни.** `GET /health` → `{"ok":true,"version":"…","protocol":1}`.

## Как устроено

```
server/
  src/
    main.ts          старт: настройки из окружения, БД, модули
    hub.ts           соединения: вызов → подпись → «готов», запросы, события, лимиты
    auth.ts          проверка подписи и кода доступа
    migrate.ts       миграции модулей (по шагам, под advisory lock)
    module.ts        что такое модуль: таблицы, методы, onReady, шина событий
    modules/
      index.ts       реестр модулей (порядок = порядок миграций)
      core.ts        устройства и переключатели (qa_devices, qa_flags)
      chat/          комнаты, участники, ветки, сообщения со сквозным seq, реакции, файлы чатов (HTTP)
      space/         пространства (заметка / папка), роли, приглашения, комментарии
      doc/           общие документы (обновления Yjs, слияние в снимок)
      media/         картинки, записи, тестовые файлы (HTTP)
      results/       результаты запусков блоков (HTTP)
  tests/             на настоящем встроенном PostgreSQL (входят в `npx vitest run` проекта)
  deploy/            compose.yml и .env.example для сервера
  scripts/publish.ps1  сборка и push образа
```

Протокол общий с приложением: [src/shared/transport/protocol.ts](../src/shared/transport/protocol.ts). Ключи — [src/main/transport/keys.ts](../src/main/transport/keys.ts).

**Вход.**
1. Сервер шлёт случайный вызов.
2. Приложение подписывает его своим ключом Ed25519. Ключ создаётся один раз и хранится зашифрованным средствами Windows.
3. Если на сервере задан код доступа, приложение доказывает, что знает его: присылает HMAC от вызова. Сам код по сети не передаётся.

Устройство узнаётся по отпечатку ключа.

**Новый модуль** (присутствие, документы, аналитика, задачи):
1. Папка `modules/<имя>/` с фабрикой `ModuleFactory`: `name`, `migrations`, `methods` (`<имя>.*`), при необходимости `onReady`.
2. Строка в `modules/index.ts`.
3. Методы и события — в `TransportMethods` / `TransportEvents` протокола.
4. Префикс — в `WINDOW_PREFIXES` в `src/main/transport/transport.ts`, если окна приложения должны его вызывать.

Миграции не правятся после выпуска: изменение — это новый шаг в конце списка.

## Попробовать на своём компьютере

Нужен запущенный Docker Desktop.

```powershell
docker compose -f server/compose.dev.yml up --build
```

Дальше в приложении: «Настройки → Сервер и чат» → адрес `localhost:3000`, включить «Подключаться к серверу». Новый чат — «@чат» в любой заметке; все чаты в одном месте — «@чат» → «Лента чатов».

## Публикация образа

1. Один раз:
   - `docker login <реестр>`;
   - в `server/.env` (не коммитится) строка `QA_REGISTRY=<реестр>`.
2. Перед выпуском поднять `version` в `server/package.json`.
3. Собрать и отправить:

   ```powershell
   ./server/scripts/publish.ps1           # <реестр>/qvarch/transport:<версия> и :latest
   ./server/scripts/publish.ps1 -NoPush   # только собрать
   ```

## Развёртывание на сервере

**Первый раз:**

```bash
mkdir -p ~/qvarch && cd ~/qvarch
# скопировать сюда server/deploy/compose.yml и server/deploy/.env.example → .env, заполнить .env
docker login <реестр>
docker compose pull && docker compose up -d
docker compose logs -f transport      # «qvarch-transport …: порт 3000»
```

Что заполнить в `.env`:

| Переменная | Что это |
|---|---|
| `QA_IMAGE` | `<реестр>/qvarch/transport:latest` |
| `QA_DB_PASSWORD` | пароль базы, только буквы и цифры (он входит в адрес подключения) |
| `QA_ACCESS_CODE` | код доступа; пусто — подключится любое приложение из сети |
| `QA_PUBLISH_PORT` | порт для приложений (3000) |
| `QA_SUBNET` | подсеть контейнеров. Она не должна пересекаться ни с одной сетью компании, иначе сервер перестанет видеть этих клиентов. Возьмите диапазон рядом с уже выбранным для `docker0`. |

**Обновление:** `docker compose pull && docker compose up -d` — миграции применятся при старте.

**Проверка с рабочего компьютера:**
- `Test-NetConnection <сервер> -Port 3000` — должно быть `TcpTestSucceeded : True`;
- в браузере `http://<сервер>:3000/health`.

**Резервная копия базы:** `docker compose exec db pg_dump -U qa qa > qa-$(date +%F).sql`.

**Один экземпляр.** Сервер держит открытые документы и подключения в памяти: запускайте ровно один контейнер `transport` на базу (несколько — потеряют правки друг друга и не доставят события).

**Код доступа.** Без `QA_ACCESS_CODE` подключиться может любое приложение из сети — для общего сервера задайте его.

**Шифрование.** Внутри сети соединение идёт по `ws://`. Для выхода за её пределы нужен TLS: nginx перед сервером с проксированием WebSocket на `127.0.0.1:3000`. В приложении тогда адрес `wss://…`.
