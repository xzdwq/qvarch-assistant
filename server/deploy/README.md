

## QA_DB_PASSWORD

Это пароль внутренней базы PostgreSQL, и придумываете его вы сами — брать его неоткуда. База создаётся при первом запуске уже с этим паролем. Снаружи она не открыта, к ней подключается только контейнер `transport`. Помнить пароль не нужно, он хранится только в `.env`.

Сгенерируйте его прямо на сервере:

```bash
openssl rand -hex 24
```

Берите именно hex — только буквы и цифры. Пароль подставляется в адрес подключения `postgres://qa:<пароль>@db…`, а знаки вроде `@`, `/` или `:` его сломают, `$` же в `.env` docker compose раскрывает как переменную.

Пароль задаётся один раз, при первом `up`. Если потом поменять его в `.env`, база останется со старым паролем и сервер не сможет к ней подключиться. Чтобы сменить пароль, его надо менять и внутри базы.

После заполнения закройте файл от чужих глаз: `chmod 600 .env`.

## QA_ACCESS_CODE

Это общий пароль на вход в сервер для всех приложений.

- **Пусто:** подключиться может любое приложение, которое видит сервер по сети.
- **Задан:**
  - при подключении сервер присылает случайную строку, приложение отвечает её подписью этим кодом (HMAC);
  - сам код по сети не передаётся;
  - неверный код — соединение отклоняется;
  - каждому, кто подключается, нужно ввести код в приложении: «Настройки → Сервер и чат → Код доступа». Там он хранится зашифрованным.

Сгенерировать код можно так же — `openssl rand -hex 16` — и раздать коллегам.

Чтобы сменить код: поменяйте его в `.env`, выполните `docker compose up -d` (контейнер перезапустится) и введите новый код в каждом приложении.

Учётные записи код не заменяет. Каждое приложение входит на сервер своим ключом устройства, а код только отсекает чужих.

## QA_SUBNET

Это внутренняя сеть, которую Docker создаёт для своих двух контейнеров. Снаружи она не видна, но сервер пускает в неё ответы на адреса из этого диапазона. Поэтому если какой-то ваш компьютер находится в том же диапазоне, ответы ему уйдут в Docker, и подключиться он не сможет. Docker по умолчанию берёт `172.17–172.31.x.x` и `192.168.x.x`, а такие диапазоны часто уже заняты в корпоративной сети.

Как выбрать:
1. **Посмотрите, что уже занято на сервере:**
   ```bash
   ip -4 route
   ip -4 addr
   cat /etc/docker/daemon.json   # если есть "bip" или "default-address-pools" — админы уже выбрали Docker безопасный диапазон
   ```
2. **Посмотрите, в каком диапазоне рабочие компьютеры:** `ipconfig` на своём ПК. Сюда же относятся адреса VPN.
3. **Возьмите /24, который не пересекается ни с чем из этого.** Значение из примера, `10.250.0.0/24`, подойдёт, если в сети компании нет `10.250.*`. Надёжнее всего спросить у сетевиков, какой диапазон свободен. Если в `daemon.json` задан диапазон для Docker, возьмите соседний с ним — именно это имеет в виду README.

Хватает /24 (256 адресов), контейнеров всего два.

## `docker compose logs -f transport`

Команда показывает вывод контейнера `transport`, а `-f` оставляет просмотр открытым — новые строки появляются по мере работы. После первого запуска по ней видно, что всё поднялось:

```
migrations: core#0, chat#0, …
qvarch-transport 0.9.0: порт 3000, код доступа задан
```

Если что-то не так, ошибка будет здесь: например, сервер не может подключиться к базе, потому что неверен пароль. Позже по этой же команде видно, что происходит на сервере.

Выход из просмотра — **Ctrl+C**: он закрывает только просмотр, контейнер продолжает работать. Последние строки без слежения покажет `docker compose logs --tail 50 transport`.
