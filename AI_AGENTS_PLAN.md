# План: ИИ-агенты в чатах и документах

Живой документ. Отмечать `[x]` по мере выполнения, решения фиксировать в «Журнале решений».

## Цель

1. **Личная работа.** Пользователь зовёт своего ИИ в чат заметки. Агент:
   - видит заметку, чат и всю базу документов;
   - пользуется функциями приложения;
   - пишет результат в заметку, а не только ответом в чат;
   - при необходимости создаёт папку с рабочими документами и ссылается на них.
2. **Совместная работа.** В общем документе есть общий чат. Каждый участник добавляет туда своего агента. Любого агента в чате можно позвать по `@имени`. Агент видит:
   - свою базу владельца;
   - общий документ и общую папку;
   - всю переписку как ход рассуждения.

   Агент может подготовить исследование в отдельной папке и поделиться им в чат.
3. **Любая модель.** Claude (через Claude Code или ключ API), OpenAI по ключу, OpenRouter, локальные модели Ollama, любой OpenAI-совместимый сервер.
4. **Ссылки на задачи и события** в общем документе раскрываются у всех участников: описание задачи, статус, время события. Это нужно и людям, и агентам для контекста.

Принцип: **делаем просто**. Механизмы из pi/durable и Odysseus пока не берём (см. «Отложено»).

## Решения

### 1. Универсальное подключение моделей

**Провайдеры — реестр** `shared/agent/providers.ts`. Одна запись — один провайдер:

| Поле | Значение |
|---|---|
| `id` | Идентификатор провайдера |
| `title` | Название в интерфейсе |
| `protocol` | `claude-code` / `anthropic` / `openai` |
| `baseUrl` | Адрес по умолчанию |
| `key` | Нужен ли ключ: `required` / `optional` / `none` |
| `models` | Как получить список моделей |

| Провайдер | Протокол | Ключ | Адрес |
|---|---|---|---|
| Claude Code | `claude-code` (внешний агент) | Нет, используется вход Claude Code | — |
| Anthropic API | `anthropic` (Messages API) | Да | `https://api.anthropic.com` |
| OpenAI | `openai` (Chat Completions) | Да | `https://api.openai.com/v1` |
| OpenRouter | `openai` | Да | `https://openrouter.ai/api/v1` |
| Ollama | `openai` | Нет | `http://localhost:11434/v1` |
| Свой сервер (LM Studio, vLLM…) | `openai` | Необязательно | Указывает пользователь |

**Два способа работы — реестр исполнителей по `protocol`:**
- **`claude-code`** — внешний агент со своим циклом. Запускается `claude -p` через `ProcessSupervisor`. Инструменты приложения получает через наш MCP-сервер с токеном хода.
- **`anthropic` / `openai`** — **наш цикл агента в main**:
  1. Модель получает пакет контекста и описания инструментов.
  2. Приложение выполняет вызванные инструменты напрямую через тот же реестр, что и MCP.
  3. Повторяет, пока модель не ответит текстом. Не больше `MAX_STEPS` шагов.

  Модели без вызова инструментов (часть моделей Ollama) работают в режиме «только ответ»: им передаётся пакет контекста без инструментов. Ошибка «модель не умеет вызывать инструменты» определяется по ответу сервера.
- Сетевые запросы — через `fetch` main, без SDK: двух протоколов достаточно для всех провайдеров.

**Профили агентов.** У пользователя может быть несколько агентов, например «ИИ · Виктор» на Claude и «ИИ · Виктор (локальный)» на Ollama. В профиле:
- имя;
- провайдер и модель;
- адрес, если отличается;
- ключ — в safeStorage, в интерфейсе не показывается;
- инструкции;
- папки базы знаний;
- путь к проекту;
- корень для рабочих папок.

Кнопка «Проверить» выполняет короткий запрос к модели. Список моделей подгружается из `/models` (у Ollama — `/api/tags`).

### 2. Авторизация

| Звено | Как | Действие пользователя |
|---|---|---|
| Агент → модель | Claude Code — его вход. Остальные — ключ в профиле (safeStorage). Ollama — без ключа | Один раз: вставить ключ или нажать «Подключить Claude Code» |
| Агент → приложение | Наш цикл вызывает инструменты напрямую. Claude Code — **токен хода** во временном `--mcp-config`: приложение знает по нему комнату, документ и автора вызова, токен гаснет после хода | Ничего |
| Агент → хаб | Агент к хабу не подключается. Его сообщения отправляет устройство владельца с полем `agent`. Хаб принимает это поле только от владельца агента | Кнопка «+ ИИ» в чате |

Общий токен MCP переносим в safeStorage.

### 3. Агент как участник чата

- Агент привязан к устройству владельца. Имя по умолчанию «ИИ · <имя владельца>», его можно изменить. В одной комнате имена уникальны; при совпадении добавляется суффикс.
- Добавляет и убирает агента только его владелец.
- Модель:
  - у комнаты — список агентов `ChatRoom.agents: Array<{ id, name, owner }>`;
  - у сообщения — поле `agent?: { id, name }`: `author` остаётся устройством владельца.
- **Упоминания** работают по участникам и агентам одинаково. `mentionsIn` / `mentionParts` принимают общий тип «участник» `{ id, name }`.
- **Настройка комнаты «Звать чужих агентов»** (`agentsOpen`), по умолчанию **выключена**:
  - выключена — агента запускает только сообщение его владельца;
  - включена — сообщение любого участника.

  Меняет создатель комнаты (в общей заметке — участник с правом `manage`).
- Статус «ИИ работает…» передаётся через существующий `chat.typing` с полем `agent`.
- **Без зацикливания:** один ход за раз на агента; новые упоминания ждут в очереди; глубина цепочки агент → агент не больше 3 (счётчик `chain` в сообщении).

### 4. Контекст хода — главное

Агент видит документ и чат **как материал для рассуждения**: без ролей и пометок, кто есть кто. Вызов агента — обычное сообщение с вопросом и предысторией. Вызов чужого агента ничем не отличается.

Каждый ход строится **заново** из пакета контекста — одинаково для всех провайдеров. Пакет собирает чистая функция `shared/agent/contextPack.ts`, по бюджету символов модели:

```
Ты — «ИИ · Виктор». Идёт обсуждение в документе «<название>» (<путь>).

Документ:
<текст; если длиннее бюджета — оглавление и начало, остальное — инструмент doc_read>

Ссылки в документе:
- [[Требования]] → заметка «Аналитика/Требования.md»
- qvarch://jira/ABC-1 → задача «…», статус «В работе» (описание — link_read)
- qvarch://event/… → событие «…», 12 окт 10:00–11:00
- [[Нет такой]] → не найдено

Рядом в папке: <заметки и файлы>

Обсуждение:
Анна: …
ИИ · Борис: …
Виктор: @ИИ · Виктор, подготовь запросы по …   ← на это нужно ответить
```

Правила пакета:
- **Вопрос** — сообщение, где упомянули агента. История — «Имя: текст» по времени; люди и агенты выглядят одинаково. Вложения — одной строкой.
- **Бюджет.** Если не помещается, сначала сокращается старая часть обсуждения («… ещё N сообщений — `chat_history`»), потом документ (оглавление + начало).
- Блоки чатов в документе заменяются строкой «[чат]», большие выводы блоков не вставляются.
- **Ссылки** разбирает реестр видов ссылок (`shared/notebook/links.ts`). Задачи и события берутся из локальных данных или из карточки общего документа (решение 6). Содержимое заметок по ссылкам агент дочитывает сам.

**Инструменты** — один реестр для MCP и нашего цикла:

| Инструмент | Что делает |
|---|---|
| `doc_read` | Текущий документ целиком |
| `link_read` | Открывает ссылку любого вида: заметку, раздел, общую заметку, задачу с описанием, событие, файл |
| `notes_search` | Полнотекстовый поиск по хранилищу: личные заметки и общие папки |
| `notes_list` (есть) | Содержимое папки |
| `chat_history` | Более ранние сообщения |
| `chat_file_read` | Вложение или файл из чата |
| `doc_section` | Вставить или заменить раздел текущего документа |
| `note_create` / `note_edit` / `folder_create` (частично есть) | Рабочие документы |
| `share_to_chat` | Поделиться документом в чат (решение 5) |
| `note_run`, `jira_issue`, … (есть) | Функции приложения |

### 5. Запись результатов и общий доступ

- В текущий документ: `doc_section` (свой раздел у каждого агента) и `note_edit`. Общий документ правится **через окно**, как `mcpBridge` сейчас.
- Своя рабочая папка: `folder_create` + `note_create`, документы связываются через `[[…]]`.
- `share_to_chat(path, mode)`:
  - файл уже в общей папке этого чата — ссылка `[[…]]`;
  - `share` — заметка становится общей (`space.share`), участники комнаты получают доступ на чтение (новый метод хаба `space.grantRoom`), в чат уходит ссылка `qvarch://doc/<id>`;
  - `forward` — снимок Markdown-файлом во вложении.
- **Агента позвал не владелец.** Агент читает базу владельца, отвечает в чат и пишет только в общий документ. Личные заметки владельца не меняет, блоки не запускает, его документами без подтверждения владельца не делится. Набор инструментов выбирается по автору вызова — по полю `access` в реестре.
- `guardHosts` и очистка секретов работают как сейчас.

### 6. Карточки задач и событий в общем документе

**Проблема.** Чип `qvarch://jira/KEY` и `qvarch://event/…` разворачивается только у того, у кого задача есть в кэше Jira, а событие — в таймлайне. Остальные видят голый текст или «событие удалено». Описания задачи нет ни у кого.

**Решение.** В Yjs-документе общей заметки, рядом с `origins`, — карта `refs`: адрес ссылки → **карточка-снимок**.
- Модель — объединение по `kind` в `shared/transport/refCards.ts`:
  - `jira`: ключ, название, статус, категория, тип, исполнитель, приоритет, срок, описание (Markdown, до 20 000 символов), адрес задачи;
  - `event`: название, вид (подпись и цвет), начало, конец, задача, Outlook, атрибуты текстом.

  У обоих вариантов есть поля `by` (устройство) и `at` (часы сервера).
- **Кто пишет.** Приложение участника с правом правки, у которого заметка открыта или синхронизируется. Для каждой ссылки `qvarch://` в тексте, о которой у него есть **свежие локальные данные**, приложение записывает карточку, если содержимое отличается от записанного (без учёта `by` и `at`). Карточки ссылок, которых больше нет в тексте, удаляются. Запись идёт с задержкой, одним изменением.
- **Кто читает — все.** Чип берёт данные так: локальные свежие, иначе карточка. У данных из карточки подсказка «по данным <имя>, <когда>». «Событие удалено» показывается только тогда, когда нет ни локального события, ни карточки, а заметка личная. В общей заметке без данных пишется «нет данных».
- **Развернуть.** Клик по чипу задачи открывает всплывающую карточку (`Popover`): название, статус, исполнитель, срок, описание. Кнопка «Открыть в Jira» — по своему адресу Jira или по адресу из карточки. Чип чужого события открывает карточку только для чтения; своё событие — как сейчас.
- **Для агента** `link_read` и пакет контекста используют тот же порядок: локальные данные, иначе карточка.
- Читатели и комментаторы карточек не пишут: у них нет права правки, хаб их изменения не примет.

## Пограничные случаи

- **Владелец агента не в сети.** В меню `@` агент помечен «не в сети». Пропущенные упоминания обрабатываются после входа: один ход на комнату.
- **Упомянули сразу двух агентов.** Ходы идут параллельно, каждый агент пишет в свой раздел.
- **Агент упомянул агента.** Действуют правила `agentsOpen` и лимит `chain`. Агенты одного владельца могут звать друг друга всегда.
- **Два устройства у одного владельца.** У каждого устройства свои агенты, к имени добавляется суффикс.
- **Модель без инструментов** (Ollama) — режим «только ответ». **Ollama не запущена** — ошибка «нет связи с <адрес>» в карточке хода.
- **Ключ неверный или кончились деньги.** Текст ошибки провайдера в карточке хода. Ключ и заголовки в журнал и чат не попадают.
- **Длинный ответ** (больше 8000 символов) — длинное в документ, в чат итог со ссылкой.
- **Цикл инструментов не сходится** — стоп на `MAX_STEPS`; в чат уходит то, что есть, с пометкой.
- **Падение посреди хода.** После рестарта в чат пишется «ход прерван», сам ход не повторяется.
- **Нужен запуск блоков, а окно с заметкой не открыто** — `mcpBridge` открывает её в фоне без кражи фокуса.
- **Карточки:**
  - двое одновременно записали одну карточку — в Yjs побеждает одна запись, обе свежие, это нормально;
  - описание задачи огромное — обрезается до лимита с пометкой;
  - доступ к Jira потерян — карточка остаётся, пока кто-то другой её не обновит;
  - ссылку удалили — карточку удаляет следующий редактор.
- **Ссылка на личную заметку в общем чате** — у других «недоступна»; у владельца кнопка «Поделиться».
- **Перенос локального чата прервался** — повтор идемпотентен (`id` комнаты + `clientId` сообщений).

### Этап 5. Агент — полноценный автор документа
- [x] **Строки, написанные ИИ, помечены**:

  - Общая заметка: метка правки в Yjs получает `g` — имя агента. Правка человека явно стирает `g` (`g: null`), иначе формат унаследовался бы.

### Этап 6. Чат как мессенджер, остров
- [x] **Полоса ИИ**:
  - сплошная, без разрывов: пустые и служебные строки между строками одного агента — его;
  - конец строки считается только у пустой строки, поэтому строка, вставленная после чужой, не перекрашивает её;
  - ✦ крупнее, слева от полосы.
- [x] Карточка задачи или события закрывается повторным кликом по той же метке: `PopoverPoint.from`.
- [x] **Вид чата как в Telegram**:
  - скругления везде;
  - фон-градиент под сообщениями (`--chat-wall`);
  - свои пузыри — один градиент на весь вид (`--chat-mine fixed`);
  - поле ввода вынесено в `ChatComposer`.
- [x] **Ответ на сообщение**:
  - кнопка или двойной клик; цитата над полем;
  - в сообщении — цитата, по клику прокрутка к оригиналу (догружаются старые страницы);
  - сервер хранит снимок оригинала (`reply jsonb`), локальные чаты и перенос истории — тоже;
  - ИИ отвечает ответом на вопрос, который его позвал.
- [x] **Голосовые**:
  - микрофон вместо «Отправить», пока поле пустое; Esc — отмена; до 15 минут;
  - файл чата вида `voice`, плеер в сообщении;
  - в чате без сервера — понятная ошибка.
- [x] **Частые реакции первыми**: счётчики в `data/reactions.json`, пусто — обычный набор.
- [x] **Остров**:
  - **Счётчики.** Непрочитанные сообщения и напоминания видны всегда: на сфере, в прилипшей пилюле, в шапке панели. Уведомления чата на них не влияют.
  - **Режим сферы.** Сфера открывает заметку или чат; режим запоминается (`IslandPrefs.orb`).
  - **Окно чата.** Последние сообщения и ответ.
    - Выбор: конкретный чат или лента (`IslandPrefs.chatRoom`); в ленте открывается чат с новыми сообщениями.
    - Пока окно открыто, чат не подменяется.
    - Чаты листаются ‹ ›, у каждого свой черновик.
  - **Устройство.** Чаты живут в главном окне.
    - Главное окно сообщает острову краткое состояние.
    - Просьбы острова идут через main в главное окно (`WindowAsk`, общий с MCP).
  - **Напоминания.** Показываются и в острове: всплывают на 12 с, ждут, пока их не посмотрят, открывают событие.

Пограничные случаи этапа:
- главное окно закрыто — остров получает понятную ошибку;
- старый сервер не знает вида `voice` — сообщение об ошибке при отправке;
- сообщение, на которое ответили, ещё не загружено — догружается до 20 страниц;
- перенос истории локального чата: номера сообщений совпадают, поэтому ответ находит оригинал.

- [x] Агенты в чате сверяются с профилями:
  - профиль удалён — его агент убирается из всех чатов;
  - профиль переименован — имя агента в чатах обновляется.

  Сверка идёт при каждом изменении списка чатов, так что повисшие агенты тоже уберутся. Ошибка — повтор при следующей сверке (`shared/agent/roomAgents.ts`).

### Этап 7. Чужой вызов и длинные обсуждения (позже)
- [ ] **Видимость по чужой просьбе.** Агента позвал не владелец — агент видит только:
  - историю этого чата;
  - документ, в котором чат;
  - либо все общие документы, которые есть у владельца и у того, кто спросил.

  Личные заметки владельца недоступны: ни поиск, ни чтение, ни переход по ссылкам из общего документа в личные.
  Запрещено, как и сейчас: создавать, удалять и менять что-либо вне общего блокнота.
- [ ] **Чужой ИИ не ответил.** Нет «работает…» за ~30 с — у позвавшего под сообщением пометка: «ИИ · Имя пока не ответил — владелец, возможно, не в сети; ответит, когда появится (в течение суток)».
- [ ] **Ошибки агента.** Проверить, что любая ошибка (нет ключа, нет Claude Code, ошибка модели, запрещённый инструмент) доходит до чата понятным текстом, в том числе при чужом вызове.
- [ ] **Сжатие истории.**
  - Старая часть обсуждения сворачивается в сводку: решения, договорённости, открытые вопросы, факты, ссылки.
  - Сводка хранится у чата и дополняется по мере роста, а не пересчитывается целиком.
  - Агент получает сводку и последние сообщения целиком; старое по-прежнему достаётся `chat_history`.

## Отложено

- Журнал прогонов «намерение → эффект → итог»: что агент изменил, откат его правок. Сейчас есть только «Шаги ИИ» в ответе.
- Переподключение окна к идущему ходу.

Не делаем:
- вмешательство в работу агента на ходу (`steer`);
- подтверждения по хэшу с TTL.
