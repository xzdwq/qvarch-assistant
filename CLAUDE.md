# Qvarch Assistant

Десктопное приложение на Electron + Vue 3 + TypeScript. Что в нём есть:
- учёт времени и задачи;
- блокнот с исполняемыми блоками: HTTP, SQL, JS/TS, Playwright, циклы, шаблоны, таблицы;
- встроенный браузер с проверками и картой API;
- HTTP-клиент, терминал, релизы.

## Как работать

- Отвечать по-русски.
- **Сборка** — в PowerShell, через `fnm env --use-on-cd | Out-String | Invoke-Expression; fnm use 22.20.0`:
  1. `npm run typecheck`;
  2. `npx vitest run`;
  3. поднять `version` в `package.json`;
  4. `npm run dist`.

  Результат — `dist\Qvarch Assistant <версия> portable.exe`.
- **Приложение не запускать и не закрывать** — только собирать и называть файл. Старые сборки не удалять.
- Не коммитить. Ничего не писать в Jira.
- **Проверка интерфейса** — только в изолированном скрытом профиле: без всплывающих окон и без кражи фокуса. В скрытом окне клик не вызывает событие `focus`, поэтому поля и всплывающие меню проверяются реальным вводом с клавиатуры.
- **Код не править через bash heredoc / sed / `node -e`**: они портят обратные слэши. Править через Edit/Write или скриптом, записанным через Write.
- **Перед кодом:** перечислить сложные и пограничные случаи, составить план, потом писать. Никаких быстрых заплаток.

## Продукт и интерфейс

- **Никаких названий** локальных проектов, стендов, веток и задач — ни в коде, ни в тестах, ни в интерфейсе. Формулировки нейтральные.
- **Компактность:**
  - варианты одного действия — одна кнопка с меню;
  - где понятно без подписи — только иконка;
  - кнопки в одном ряду одной высоты;
  - заголовки в одну строку: при нехватке места прячется второстепенное, перенос строк запрещён.
- **Любое всплывающее меню:**
  - через `Teleport` в `body` и `lib/floating` (`placeFloat` + `useAnchor` / `useFollow` / `useCloseOnScroll`);
  - держится за свою кнопку при прокрутке и закрывается, когда она ушла с экрана;
  - нативный `<datalist>` запрещён — использовать `SuggestInput`.
- **Блоки заметки:** `contain: inline-size; min-width: 0`. Широкое содержимое прокручивается внутри и никогда не расширяет заметку.
- **Секреты** (токены, cookie) в ответах не печатать.

## Код

- Комментарии короткие, на английском, в стиле существующего кода. Названия — по смыслу.
- **Без костылей и чёрных списков:** механизмы универсальные, поведение привязано по смыслу (адаптеры, правила), а не по частным случаям.
- **Нет цепочек `if / else if` по типу.** Вместо них реестр, таблица соответствий или `switch` по объединению типов с исчерпывающей проверкой.
- **Размер:** компонент — до ~400 строк, модуль — одна ответственность. Дублирование (списки названий, типов, обработчиков) запрещено.
- **Тесты:** доменная логика покрывается vitest в той же задаче.

## Целевая архитектура: гексагональная (порты и адаптеры)

Это цель рефакторинга. Переходим поэтапно, по образцу «душителя» (strangler): приложение работает после каждого этапа. На каждом этапе — тесты, проверка типов и сборка.

### Слои и правило зависимостей

```
domain  ←  application  ←  adapters (main / ipc / renderer)
```

- **`domain/`** — чистый TypeScript, без Electron, Vue, Node и ввода-вывода.
  - Сущности, объекты-значения, правила: разбор заметки и блоков, цикл, модель таблицы, карта API, защита и подстановка параметров в SQL, таймлайн.
  - Ошибки возвращаются типизированными результатами, а не исключениями.
- **`application/`** — сценарии использования (сервисы): `RunBlock`, `RunLoop`, `RunNote`, `CollectApiMap`, `ExportTable` и т. д.
  - Работают только через порты, объявленные здесь же (`application/ports`): `VaultPort`, `RunStorePort`, `HttpPort`, `SqlPort`, `CodeRunnerPort`, `PlaywrightPort`, `BrowserNetPort`, `SettingsPort`, `ClockPort`.
  - Код не знает, где он исполняется: в main или в renderer.
- **`adapters/`** — реализации портов и вход/выход:
  - `adapters/main` — файловая система, драйверы БД, процессы-исполнители (`utilityProcess`), CDP браузера, окна;
  - `adapters/ipc` — **один типизированный контракт** каналов (запрос → ответ, события). Мост preload и клиент строятся по нему автоматически, ручного дублирования нет;
  - `adapters/renderer` — Vue: экраны, компоненты, composables. В application ходит через порты, реализованные IPC-клиентом.
- **Точки сборки** (composition root): по одной в main и в renderer. Только там создаются адаптеры и внедряются в сервисы.

### Ограниченные контексты

Каждый контекст — свой срез `domain` / `application` / `adapters`:
- **tracker** — время, задачи, календарь;
- **notebook** — заметки, блоки, выполнение;
- **browser** — вкладки, запись, проверки, карта API;
- **integrations** — Jira, Outlook, HTTP, SQL, терминал;
- **release**.

### Ключевые решения

- **Реестр типов блоков.** У каждого типа одна запись (класс или описание) и своя папка `notebook/blocks/<kind>/`. В записи в одном месте собраны:
  - распознавание в Markdown, разбор и запись;
  - название и иконка;
  - компонент;
  - исполнитель (стратегия);
  - команда «@»;
  - оценка высоты.

  `NoteBlockHost`, меню «@», «Выполнить всё», перетаскивание и отчёты делают поиск в реестре. Новый блок — это одна папка.
- **Окружение выполнения** — классы: `RunEnv` → `NoteEnv` / `PassEnv`. Значения, публикация, хранение результатов и id остановки инкапсулированы в них.
- **Надзор за процессами в main** — один класс для запусков кода, циклов, Playwright и SQL. Он отвечает за старт, стоп, таймаут, окно-владельца и защиту от событий устаревшего процесса.
- **Всплывающие меню** — один `usePopover` и компонент `<Popover>`. Все меню построены на них.
- **Таблица** — одно ядро: модель, выделение, буфер обмена, экспорт. Его используют таблица заметки, результат SQL и вывод цикла.
- **`MdEditor`** — собирается из расширений CodeMirror: `livePreview`, `components`, `loopBands`, `commandMenu`, `dragDrop`, `valueChips`. Сам компонент только их подключает.
- **Немного ООП:** у сервисов, адаптеров и сущностей с поведением — классы. Данные между слоями (DTO) — простые объекты. Состояние — хранилища по контекстам за composables.

### Порядок переноса

1. Блокнот:
   - реестр блоков и команд;
   - движок выполнения на `RunEnv`;
   - разделение `MdEditor`.
2. IPC-контракт и надзор за процессами.
3. Браузер: проверки и карта API.
4. Остальные контексты.
