# Qvarch Assistant

Десктопное приложение на Electron + Vue 3 + TypeScript. Что в нём есть:
- учёт времени и задачи;
- блокнот с исполняемыми блоками: HTTP, SQL, JS/TS, Playwright, циклы, шаблоны, таблицы;
- встроенный браузер с проверками и картой API;
- HTTP-клиент, терминал, релизы.

## Как работать

- Отвечать по-русски.
- **Сборка** — в PowerShell, через `fnm env --use-on-cd | Out-String | Invoke-Expression; fnm use 22.20.0`:
  1. `npm run typecheck`;
  2. `npx vitest run`;
  3. поднять `version` в `package.json`;
  4. `npm run dist`.

  Результат — `dist\Qvarch Assistant <версия> portable.exe`.
- **Приложение не запускать и не закрывать** — только собирать и называть файл. Старые сборки не удалять.
- Не коммитить. Ничего не писать в Jira.
- **Проверка интерфейса** — только в изолированном скрытом профиле: без всплывающих окон и без кражи фокуса. В скрытом окне клик не вызывает событие `focus`, поэтому поля и всплывающие меню проверяются реальным вводом с клавиатуры. Сверка вида до и после правки — `scripts/parity` (см. `.claude/rules/styles.md`).
- **Код не править через bash heredoc / sed / `node -e`**: они портят обратные слэши. Править через Edit/Write или скриптом, записанным через Write.
- **Перед кодом:** перечислить сложные и пограничные случаи, составить план, потом писать. Никаких быстрых заплаток.

## Продукт и интерфейс

- **Никаких названий** локальных проектов, стендов, веток и задач — ни в коде, ни в тестах, ни в интерфейсе. Формулировки нейтральные.
- **Компактность:**
  - варианты одного действия — одна кнопка с меню;
  - где понятно без подписи — только иконка;
  - кнопки в одном ряду одной высоты;
  - заголовки в одну строку: при нехватке места прячется второстепенное, перенос строк запрещён.
- **Любое всплывающее меню** — на `usePopover` / `<Popover>` (`lib/usePopover.ts`, `components/Popover.vue`):
  - переносится в `body`, держится за свою кнопку при прокрутке и закрывается, когда она ушла с экрана;
  - Esc закрывает последнее открытое меню и дальше не идёт;
  - повторный клик по кнопке, открывшей меню, закрывает его;
  - нативный `<datalist>` запрещён — использовать `SuggestInput`.
- **Блоки заметки:** `contain: inline-size; min-width: 0`. Широкое содержимое прокручивается внутри и никогда не расширяет заметку.
- **Секреты** (токены, cookie) в ответах не печатать.

## Код

- Комментарии короткие, на английском, в стиле существующего кода. Названия файлов, функций и методов — по смыслу (их читают люди, ИИ и графы кода).
- **Без костылей и чёрных списков:** механизмы универсальные, поведение привязано по смыслу (адаптеры, правила), а не по частным случаям.
- **Нет цепочек `if / else if` по типу.** Вместо них реестр, таблица обработчиков или `switch` по объединению типов с исчерпывающей проверкой.
- **Наборы значений** (виды, режимы, состояния, методы, вкладки) — один `as const` массив или таблица в модуле констант своего контекста, тип выводится из него. Одиночное сравнение с типизированным значением (`state === 'run'`) допустимо — его проверяет компилятор.
- **Без демо-данных в коде:** примеры и стартовые наборы не зашиваются; встроенные определения — реестром (одна запись = имя, описание, поведение).
- **Размер:** файл — до ~400 строк, модуль — одна ответственность. Дублирование (списки названий, типов, обработчиков) запрещено.
- **Тесты:** доменная логика покрывается vitest в той же задаче. Тесты собираются через `tsconfig.node.json`, он не видит `src/renderer` — поэтому чистая логика лежит в `src/shared`.
- **Немного ООП:** у сервисов и сущностей с поведением — классы; данные между слоями — простые объекты; состояние экрана — composables и provide/inject.

## Архитектура (кратко)

Прагматичное разделение по слоям и контекстам — без догмы портов и адаптеров:

- **`src/shared`** — чистый TypeScript без DOM, Vue и Electron: модели, правила, разбор, константы контекстов (`shared/<контекст>/`). Импорты внутри — только относительные.
- **`src/main`** — точка сборки `index.ts`, обработчики IPC по областям (`main/ipc/`), сервисы контекстов (`main/<контекст>/`), процессы-исполнители через `ProcessSupervisor`.
- **IPC** — один типизированный контракт `QA_ROUTES`; мост preload строится по нему сам.
- **`src/renderer`** и **`src/notebook`** (`@nb`) — Vue: экран — тонкий корень, части и composables рядом, общее состояние через provide/inject.
- **Стили** — Tailwind v4 с префиксом `tw:`, цвета — только CSS-переменные.

Контексты: **tracker** (время, задачи, календарь, island), **notebook** (заметки, блоки, выполнение), **browser** (вкладки, запись, проверки, карта API), **integrations** (настройки, терминал, HTTP, Jira, Outlook), **release**, **инструменты** (доска, кодировки, PDF).

Подробно «где что» — в `.claude/rules/`: `notebook.md`, `main-ipc.md`, `contexts.md`, `styles.md` (подгружаются, когда работа идёт в их файлах).
